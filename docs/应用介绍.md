# 白的百宝箱

> **拖进来，点一下，能读了。**

一个 Windows 桌面工具，专治一件事：**手里有个日文 / 英文游戏，看不懂，想玩。**

---

## 它解决什么问题

想玩一个外文游戏，通常的流程是这样的：

先在搜索引擎里翻半天"这游戏怎么汉化"；然后被指到某个论坛的某个帖子；帖子里让你装一个工具，
再装一个补丁，再手动改一个配置文件；改完发现字体是方块；再去装字体；字体装完发现文字
溢出了对话框，被裁掉一半；最后进了游戏，发现有个 NPC 的名字翻错了，但你已经没有力气去改。

**白的百宝箱想把这些压缩成三步。**

---

## 怎么用

### 第 1 步：选游戏目录

打开应用，点「选择目录」，指到游戏根目录。

选完**立刻**会告诉你识别到了什么引擎 —— 所以如果选错了目录，你马上就知道了，
不用等跑完一轮才发现。

### 第 2 步：确认选项

源语言、目标语言、要不要注入中文字体、要不要试译一小段先看效果。

如果你还没配翻译接口的密钥，这里会明确告诉你：**现在用的是"本地假机翻"，
译文长得像 `【中】原文`，它只用来验证流程能跑通，不是真翻译。**
（在「配置」页填上密钥就会换成真的机翻。）

### 第 3 步：点「开始汉化」

然后就能看到进度：抽取 → 入库 → 查翻译记忆 → 翻译 → 回写 → 注入字体，每一步都有百分比。

跑完给你一份明细：抽到多少条、新入库多少、翻译成功多少、**控制符冲突多少**（这些会被
**拒绝写回**，因为它们的占位符对不上，硬写进去会破坏游戏文本）。

进游戏玩就是了。

### 不满意？一键还原

不管因为什么原因不满意 —— 翻得不好、界面变丑、想换一个模型重来 ——
点「一键还原」，**游戏会回到你打开这个工具之前的样子**，逐字节一致。

这不是"尽力还原"，是每次都验证过的：改之前自动备份，还原后比对哈希。

## 它具体能做什么

### 汉化

- **对白、旁白、选项、道具说明、技能描述、角色名** —— 凡是给人看的文字都会抽出来翻译。
- **翻译前把控制符（`\C[1]`、`\V[3]` 这类）先扣出来、翻完再装回去**，
  所以颜色、图标、变量替换在译文里仍然正确。装不回去的会被拦下来，不会带着错误写进游戏。
- **翻译记忆**：同一个游戏跑第二遍，已经翻过的一句都不会再送出去翻，省钱也省时间。
- **术语表**：人名地名可以固定译法，不会出现同一个角色在三段对话里有三个名字。

### 人工修订工作台

机翻总有翻得别扭的地方。这里可以：

- 按**文件**浏览所有文本，或直接**搜索**原文/译文；
- 按状态筛选：**未译 / 已译 / 已复核 / 冲突**；
- 点开任意一条**直接改**，改完就存；
- **批量替换** —— 而且会先**给你看前后对比的样例**，确认了才真改
  （这是不可逆的批量操作，只报"改了 300 条"你没法判断改得对不对）；
- **导入导出**译文包（JSON，无损，状态下也能带回来）；
- 看一下**覆盖率**，知道翻到哪儿了。

改完不用重跑整条流水线 —— 有一个单独的**「回写到游戏」**，只把改动落进游戏文件。
（它只会写"已译/已复核"的条目；"未译"和"冲突"的**永远不会**被写进去。）

### 配置

- 翻译接口的**密钥、地址、模型**、批大小、并发数、默认翻译方向；
- 密钥用系统的加密存储保存（Windows 上是 DPAPI，绑定当前用户）；
- 界面上**读不回**已保存的密钥，只能覆盖或清除。

### 日志

打包后的程序没有终端 —— 如果哪天它"不动了"，这里能看到刚才到底发生了什么：
识别引擎、开始汉化、每批翻译、回写结果、报了什么错。
出问题想找人帮忙时，点「复制全部」把这段贴出来即可。

### 命令行

不想开界面，或者要批量处理的话：

```bash
白的百宝箱.exe --game "D:\games\某游戏" --limit 30      # 先试译 30 条看看
白的百宝箱.exe --game "D:\games\某游戏" --no-repack     # 只抽取入库，先检查抽得准不准
白的百宝箱.exe --game "D:\games\某游戏"                 # 完整跑一遍
白的百宝箱.exe --game "D:\games\某游戏" --repack-only   # 只回写（工作台改完之后）
白的百宝箱.exe --game "D:\games\某游戏" --restore       # 一键还原
```

## 支持哪些游戏

| 引擎 | 状态 | 说明 |
|---|---|---|
| **RPG Maker MV** | ✅ 可用 | 实测某真实游戏抽出 **4064 条**文本，控制符零损失 |
| **RPG Maker MZ** | ✅ 可用 | 实测某真实游戏抽出 **7487 条**文本 |
| **Ren'Py** | ✅ 可用 | 支持 `.rpy` 脚本的解析与回写 |
| Unity | ⏳ 后续版本 | 基础设施（资源容器解析）已有，但对象枚举还不工作，**这一版不投入** |
| KiriKiri | ❌ 不支持 | 本机没有可用样本、无法验证，已从计划中移除 |

> 没有样本就无法验证，无法验证就不叫"支持" —— 所以这里只列真的测过的。

### 顺带说一句"排版"

日文换成中文之后，字符宽度会变，原本一行放得下的句子可能就溢出了。
**MV / MZ 本身没有横向自动折行**，所以我们给它补上了（含中文标点的避头尾规则：
句号、逗号不会跑到行首，左括号不会吊在行尾）。

**Ren'Py 不需要** —— 它自带专业排版引擎和中日韩断行规则，我们只给它补了字体。

这两个引擎在这件事上的做法完全相反，都是**先侦察、跑真游戏实测**之后才知道的。

### 字体

中文显示成方块，是因为游戏的字体里没有汉字。这里的做法是**让引擎去用系统里已有的中文字体**，
**不往你的游戏目录里塞任何字体文件**（那涉及字体授权）。具体改哪里：

- **MV**：改 `System.json` 的 `locale`
- **MZ**：改 `advanced.fallbackFonts`
- **Ren'Py**：用 `FontGroup` 给汉字加字体回退，**保留游戏原本的装饰字体**（标题那种花体字不会被换掉）

## 三条承诺

**① 一切可逆。**
任何改动游戏文件的操作，之前都自动备份；「一键还原」会把补丁按倒序展开，
回到你打开这个工具之前的状态。这不是口头保证 —— 每次交付前都在真实游戏上验证过
"还原后逐字节一致"。

**② 不偷偷上传任何东西。**
翻译记忆、术语表、文本库全在你本机。除了你自己配置的翻译接口，
没有任何一个字节会离开这台机器。没配密钥时就用本地假机翻 —— 而不是"悄悄发到某个服务器"。

**③ 不碰反检测、不绕杀软。**
不做任何针对杀毒软件或反作弊的规避。这个项目解决的是"看不懂"，不是"绕过什么"。

---

## 现在的已知限制

- **真翻译需要一个翻译接口的密钥。** 没有也能用，但那是本地假机翻，只用于验证流程。
- **数据被加密的游戏处理不了。** 有些游戏会加密自己的数据文件。这种情况会被**明确拒绝**
  并告诉你原因，而不是把文件改坏。（处理这类游戏需要"运行时提取"，是后续的工作。）
- **MZ 的插件指令文本**（写在插件参数里的那些）还没有覆盖。
- **没有应用图标、没有代码签名。** 现在用的是 Electron 默认图标；
  打开安装包时 Windows 会弹 SmartScreen 警告 —— 签名需要证书，还没做。

## 给好奇的人：为什么是"改文件"而不是"注入"

汉化这类游戏有两条路：把 DLL 注入游戏进程、在内存里改文本；或者直接解析游戏的数据文件、
改成译文再写回去。

这个工具走的是**第二条**。原因是游戏本身的构造：

- RPG Maker MV / MZ 跑在 NW.js 上，游戏逻辑是**明文 JavaScript**，文本在明文的 JSON 文件里；
- Ren'Py 跑在 Python 上，脚本是明文，而且自带翻译机制。

对这类游戏，"改文件"能做到"注入"能做的一切，却**天然避开了注入的全部风险**：
不用担进程崩溃、不用担杀毒误报、不用担 32/64 位不匹配、不用担卸载不干净。

注入留给真正啃不动的引擎 —— 那时候它才是必需的，而不是第一选择。
